# Claims Register — Data Analytics (2026-10-17)

**Purpose:** Every capability claim in the UI, README, or marketing is mapped to its evidence level. Safe wording prevents overstatement. Cross-references `docs/capability-scorecard.md`.

**Rule:** A claim cannot be listed as FULL unless engine + API route + UI screen + passing tests are all verifiable from the codebase. If any component is ORPHANED (zero application importers) or LIMITATION (infrastructure not available), the claim is downgraded.

---

## Legend

| Symbol            | Meaning                                                                                       |
| ----------------- | --------------------------------------------------------------------------------------------- |
| ✅ **FULL**       | Engine + API route + UI screen + tests; working in a running browser                          |
| ⚠️ **PARTIAL**    | Some components present but not all four, or feature is wired but untested                    |
| ⛏️ **STUB**       | Engine exists; UI or API or tests missing; deliberate refusal to fake                         |
| ❌ **ABSENT**     | No code files; feature never implemented                                                      |
| 📛 **ORPHANED**   | Engine + tests exist but zero application importers (not shipped)                             |
| ⚠️ **LIMITATION** | Real infrastructure gap (no GPU, no cluster, no deployed serving) — labeled honest limitation |
